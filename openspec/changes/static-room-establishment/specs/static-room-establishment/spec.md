## ADDED Requirements

### Requirement: 第一层必须产出有边界的固定方案空间图
第一层变更 MUST 只在当前受控范围内判断固定通信方案空间，不得承诺一定出现正例。

#### Scenario: 第一层完成时没有正例
- **WHEN** 所有确认级场景都没有固定方案同时赢得通信本身和小步整体
- **THEN** 结论必须写成 `no proven room on current controlled surface version`
- **AND** 结论必须说明该判断只绑定到本次受控范围
- **AND** 结论不得外推成所有固定方案都没有价值
- **AND** 结论不得外推成后续在线切换方向已经失败

#### Scenario: 第一层完成时出现正例
- **WHEN** 至少一个确认级场景存在通信本身和小步整体都稳定变快的固定方案
- **THEN** 该场景必须被记录为 `workload-confirmed static win`
- **AND** 结果必须给出该场景的默认对照、最佳固定方案和候选集合
- **AND** 该场景才可以进入下一层阶段变化验证

### Requirement: 第一版受控范围必须固定
第一层变更的第一版 proving surface MUST 固定为单机同插槽四卡上的 `allreduce` 固定方案比较。

#### Scenario: 生成第一版范围说明
- **WHEN** 第一层输出范围说明
- **THEN** 拓扑范围必须是 `numa1-4gpu`
- **AND** 通信类型必须是 `allreduce`
- **AND** 进程形状必须是单机四进程
- **AND** 主比较方式必须是固定候选方案回放
- **AND** 结果必须说明该版本不覆盖 `numa0-4gpu`、跨插槽八卡、阶段变化和在线切换

#### Scenario: 使用当前已实现候选方案
- **WHEN** 第一版只使用当前代码已经支持的固定方案
- **THEN** 候选集合必须至少说明 `ring/simple`、`tree/simple`、`ring/ll128` 的纳入或排除状态
- **AND** 若没有扩展更多固定方案，结论必须绑定到当前已实现候选集合
- **AND** 不得把当前候选集合当作所有可能固定方案的上限

### Requirement: 第一层必须同时判断通信本身和小步整体
第一层变更 MUST 在同一场景、同一候选方案、同一运行族内同时读取通信本身指标和小步整体指标。

#### Scenario: 判断固定方案是否赢得通信本身
- **WHEN** 某个非默认固定方案相对默认对照的目标通信耗时改善达到阈值
- **AND** 至少三次重复中的两次保持同方向改善
- **AND** 该固定方案在当前场景可用
- **THEN** 该固定方案可以被记为 `communication-positive`

#### Scenario: 判断固定方案是否赢得小步整体
- **WHEN** 某个固定方案已经被记为 `communication-positive`
- **AND** 该固定方案相对默认对照的小步整体耗时改善达到阈值
- **AND** 至少三次重复中的两次保持同方向改善
- **THEN** 该固定方案可以被记为 `workload-positive`

#### Scenario: 通信本身赢但小步整体不赢
- **WHEN** 某个固定方案被记为 `communication-positive`
- **AND** 该固定方案没有被记为 `workload-positive`
- **THEN** 对应场景必须被记录为 `communication-only win`
- **AND** 该场景不得进入下一层阶段变化验证

### Requirement: 确认阶段必须使用更像训练的小步计算形态
第一层确认阶段 MUST 使用经过校准的矩阵计算小步，或在未满足时显式记录测量形态敏感性警告。

#### Scenario: 进入确认阶段
- **WHEN** 某个候选方案从筛选阶段进入确认阶段
- **THEN** 确认阶段的首选计算形态必须是固定形状的矩阵计算
- **AND** 首选数据类型必须是 `bfloat16`，不可用时才允许使用 `float16`
- **AND** 矩阵形状、重复次数和小步边界必须在同一场景的所有候选方案之间冻结
- **AND** 若确认阶段仍使用轻量逐元素计算，证据必须记录为 harness sensitivity warning

#### Scenario: 校准确认阶段小步
- **WHEN** 为某个确认级场景校准小步计算量
- **THEN** 必须先测默认对照下目标通信的稳定耗时
- **AND** 必须用该耗时推导前置计算、重叠计算和尾部计算的相对时长
- **AND** 不得为不同候选方案分别调整计算形态

### Requirement: 默认对照路径不得被强行解释
第一层变更 MUST 保护默认对照组的路径不可观测语义，不能把诊断读数当成默认对照本身的真实路径。

#### Scenario: 汇总默认对照
- **WHEN** 第一层汇总默认对照组结果
- **THEN** 默认对照组必须作为耗时地板使用
- **AND** 默认对照组不得声明实际通信路径
- **AND** 若需要解释默认策略可能使用的路径，只能使用只观察组作为诊断旁证

#### Scenario: 固定方案看起来等价于默认诊断路径
- **WHEN** 固定方案的观测路径和只观察组中的默认诊断路径高度相似
- **THEN** 结果必须记录 `path-equivalent to baseline diagnostic`
- **AND** 该记录只能作为解释字段
- **AND** 不得替代固定方案相对默认对照的耗时判定

### Requirement: 第一层主判定必须是扣除插件开销后的净收益
第一层变更 MUST 默认判断固定方案相对干净默认对照的净收益，而不是只判断通信路径本身是否理论更快。

#### Scenario: 固定方案相对默认对照变快
- **WHEN** 固定方案组包含观察插件和调度插件
- **AND** 默认对照组不加载观察插件和调度插件
- **THEN** 固定方案相对默认对照的改善必须被解释为扣除插件开销后的净收益
- **AND** 该收益可以进入第一层主判定

#### Scenario: 需要解释插件开销
- **WHEN** 固定方案未能胜过默认对照
- **AND** 只观察组或其他诊断组显示插件开销可能影响结论
- **THEN** 结果可以记录插件开销诊断
- **AND** 插件开销诊断不得单独把失败场景升级为正例

### Requirement: 判赢阈值必须在实验前固定
第一层变更 MUST 在运行确认级实验前固定改善阈值、重复投票规则和汇总口径。

#### Scenario: 固定默认判赢规则
- **WHEN** 第一层进入确认阶段
- **THEN** 通信本身和小步整体的默认改善阈值必须是 `2.0%`
- **AND** 默认重复投票规则必须是至少三次重复中的两次同方向
- **AND** 汇总口径必须在证据文档中提前声明
- **AND** 不得在看到实验结果后更改判赢规则

### Requirement: 晋级下一层必须依赖小步确认正例
后续阶段变化验证 MUST 只能消费第一层中已经被小步整体确认的固定收益场景。

#### Scenario: 生成晋级包
- **WHEN** 第一层输出可晋级场景
- **THEN** 每个可晋级场景必须已经被记为 `workload-confirmed static win`
- **AND** 必须记录该场景的固定比较地板
- **AND** 必须记录候选集合
- **AND** 只有这些场景可以进入 `same-key-phase-shift-validation`

#### Scenario: 没有可晋级场景
- **WHEN** 第一层没有任何 `workload-confirmed static win`
- **THEN** 晋级包必须明确为空
- **AND** 后续阶段变化验证不得从 `communication-only win` 或负例场景启动
